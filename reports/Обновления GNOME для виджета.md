# GNOME 51 решает шрифты, но не рабочий стол

Из семи проблем Modern Clock новый API GNOME 46–51 по-настоящему закрывает одну: **загрузку встроенных шрифтов без установки**. Метод `Pango.FontMap.add_font_file()` (Pango ≥ 1.56) есть в SDK GNOME 48–51, и мы его ещё не используем. Публичного API для «слоя рабочего стола» нет даже в GNOME 51, так что приватный `Main.layoutManager._backgroundGroup` остаётся де-факто стандартом: AzClock тоже на нём. Баг с прозрачным актором на втором мониторе в апстриме никто не описал и не исправил. Объяснение из нашего же поста на Discourse («Clutter не выделяет allocation в чужом stage view») не сходится с устройством Clutter. Значит, после удаления обходного `rgba(0,0,0,0.01)` нужен реальный тест на двух мониторах. Поломки API 47–51 текущий код в основном уже учитывает. Отстали документация (CLAUDE.md) и сопутствующие практики: синхронное копирование шрифтов, `fc-cache` в описании, `gschemas.compiled` в zip, совет «Alt+F2 → r». В GNOME 50 сессию X11 удалили полностью. На Wayland тестировать без выхода из сессии можно через `gnome-shell --devkit` (49+). Горячей перезагрузки расширений по-прежнему нет. Проверки EGO ужесточились: появились правило против AI-кода (декабрь 2025) и анализатор Shexli (апрель 2026), который выдаёт находки с кодами прямо на странице ревью.

## Слой рабочего стола: приватный `_backgroundGroup` остаётся единственным путём

**Подтверждено.** В текущем `main` gnome-shell `layout.js` по-прежнему создаёт `this._backgroundGroup = new Meta.BackgroundGroup()` и кладёт его в самый низ `global.window_group`. Новых методов для «фонового хрома», кроме прежних `addChrome`/`addTopChrome`, не появилось ([layout.js](https://gitlab.gnome.org/GNOME/gnome-shell/-/raw/main/js/ui/layout.js)). В NEWS gnome-shell с 46 по 51.0 нет ни одной записи о desktop-widget API ([gnome-shell NEWS](https://gitlab.gnome.org/GNOME/gnome-shell/-/raw/main/NEWS)). Layer-shell в mutter по-прежнему существует только как запрос в issue #973 ([mutter #973](https://gitlab.gnome.org/GNOME/mutter/-/issues/973)). Единственный новый поддерживаемый механизм рассчитан на **клиентские окна**. С GNOME 49 расширение может запустить Wayland-клиент через `Meta.WaylandClient.new_subprocess` и пометить его окно типом DESKTOP через `Meta.Window.set_type()` и `hide_from_window_list()` ([gjs.guide 49](https://gjs.guide/extensions/upgrading/gnome-shell-49.html)). Так сделаны DING и LiveEngine ([LiveEngine](https://github.com/gurmeetgupta22/LiveEngine)). Для часов это слишком тяжело: отдельный GTK-процесс, IPC, и только на 49+. Самое популярное похожее расширение, AzClock, по умолчанию тоже добавляет виджеты в `Main.layoutManager._backgroundGroup` ([AzClock extension.js](https://gitlab.com/AndrewZaech/azclock/-/raw/main/src/extension.js)).

**Вывод:** оставить `_backgroundGroup`. При отправке на EGO коротко обосновать использование приватного API в заметках к ревью. Shexli, вероятно, выдаст на это рекомендательную находку класса EGO-I-xxx; привязка кода EGO-I-004 к приватному API **не подтверждена** ([shexli-ci](https://github.com/3v1n0/shexli-ci)).

## Второй монитор: обходной путь удалён, а причина бага так и не доказана

**Подтверждено:** ни в одном релизе mutter или gnome-shell 46–51 нет issue или MR с симптомом «St-актор с прозрачным фоном не рисуется на вторичном stage view». Единственное публичное описание — пост владельца репозитория на Discourse, на который разработчики GNOME не ответили ([Discourse #35924](https://discourse.gnome.org/t/rendering-a-shell-extension-widget-on-secondary-monitors-in-wayland-undocumented-fix/35924)). В Clutter allocation считается один раз на всю сцену, а не для каждого stage view. Принадлежность актора к view выводится из его трансформированных границ, а не из того, рисует ли он фон ([сигнал stage-views-changed](https://mail.gnome.org/archives/commits-list/2020-June/msg04087.html), [Clutter.Actor](https://gnome.pages.gitlab.gnome.org/mutter/clutter/class.Actor.html)). Объяснение через MetaCullable из коммита `bc2ada6` тоже не подтверждается: `cull_out_children_common()` пропускает детей, которые не реализуют MetaCullable. Обычный `St.BoxLayout` внутри `_backgroundGroup` этот механизм не отсекает вообще ([meta-cullable.c](https://gitlab.gnome.org/GNOME/mutter/-/raw/main/src/compositor/meta-cullable.c)).

**Не подтверждено (гипотезы):** настоящая причина могла быть в одном из трёх. Первое — тайминг позиционирования в старом коде (`_repositionAll()` по таймерам). Второе — неверные clip-регионы перерисовки на вторичном view. Третье — сама старая структура `St.Widget` + `BinLayout`. Похожие исправления в mutter есть: «Only queue clipped redraws when mapped» (50.1, !4990), «Fix invalid redraw clips on rotated monitors» (51.beta, !5203), «Fix multiple monitors being reported as primary» (51, !5228) ([mutter NEWS](https://gitlab.gnome.org/GNOME/mutter/-/raw/main/NEWS)). Ни одно из них не называет наш симптом. Переписанный код (`8acd79b`) создаёт виджеты одинаково для всех мониторов, позиционирует их через `get_laters()` и `notify::allocation` и использует `background: transparent`. Проверку на нескольких мониторах коммит не упоминает.

**Вывод:** проблема требует тестирования. Сценарий: Wayland, два монитора, GNOME 46 (нижняя граница) и 50/51. Проверить отрисовку после входа в сессию, после hotplug и при смене масштаба. Если часы на втором мониторе пропадают, вернуть `background-color: rgba(0,0,0,0.01)`: это практически бесплатно. Для диагностики в mutter 50.1+ можно задавать флаги отладки отрисовки из окружения (!4973). В Looking Glass стоит проверить `get_allocation_box()` и `get_stage_views()` у вторичного контейнера.

## Шрифты: `add_font_file` закрывает проблему на GNOME 48+, но с подвохом

**Подтверждено.** `pango_font_map_add_font_file()` доступна с Pango 1.56 и интроспектируется, а fontconfig-бэкенд её реализует ([docs.gtk.org](https://docs.gtk.org/Pango/method.FontMap.add_font_file.html)). В SDK GNOME версии Pango такие: 46 → 1.52.2, 47 → 1.54.0, 48 → 1.56.4, 49/50 → 1.57.1, 51 → 1.58.2 ([gnome-build-meta gnome-48](https://gitlab.gnome.org/GNOME/gnome-build-meta/-/raw/gnome-48/elements/sdk/pango.bst), [gnome-51](https://gitlab.gnome.org/GNOME/gnome-build-meta/-/raw/gnome-51/elements/sdk/pango.bst)). В Ubuntu 24.04 стоит Pango 1.52.1, в 25.04/25.10 — 1.56.3, в 26.04 — 1.57.0 ([Launchpad](https://api.launchpad.net/1.0/ubuntu/+archive/primary?ws.op=getPublishedSources&source_name=pango1.0&exact_match=true)). Начиная с 1.56.4, реализация держит шрифт **только внутри объекта font map**. Любой последующий `config_changed()` на этой карте молча его удаляет ([коммит 5ad59992](https://gitlab.gnome.org/GNOME/pango/-/commit/5ad59992.diff)). В 1.56.0–1.56.3 шрифт попадал в глобальный набор fontconfig ([коммит 096c1e8c](https://gitlab.gnome.org/GNOME/pango/-/commit/096c1e8c.diff)). Поэтому Ubuntu 25.04/25.10 ведут себя иначе, чем апстрим 48+.

Важная деталь: Clutter **не использует** `PangoCairo.FontMap.get_default()`. Он создаёт свою карту для каждого `ClutterContext`. `Clutter.get_font_map()` существовал только в mutter 46 ([mutter 47 clutter-main.h](https://gitlab.gnome.org/GNOME/mutter/-/raw/47.0/clutter/clutter/clutter-main.h), [mutter 51 clutter-context.c](https://gitlab.gnome.org/GNOME/mutter/-/raw/51.0/clutter/clutter/clutter-context.c)). Путь, который работает на всех версиях 46–51: `global.stage.get_pango_context().get_font_map()`. Отсюда **реальная ошибка в коде**: проверка поддержки шрифта в `src/lib/utils.js` (`PangoCairo.FontMap.get_default()`) обращается не к той карте, которая рисует St-метки. Кроме того, с mutter 47 shell вообще не перечитывает fontconfig во время работы ([mutter main clutter-settings.c](https://gitlab.gnome.org/GNOME/mutter/-/raw/main/clutter/clutter/clutter-settings.c)). Этим и объясняется нынешнее требование перелогиниться.

**Не подтверждено (вывод из исходников, не запускалось):** вызывать `add_font_file` нужно в начале `enable()`, до создания меток и до проверки `load_font()`. Иначе Pango может закэшировать подстановочный шрифт. `config_changed()` после этого вызывать нельзя. Удалить шрифт из карты невозможно (`remove_font_file` нет), поэтому после `disable()` он остаётся зарегистрированным до перезапуска shell. На GNOME 46/47 из GJS шрифт в процесс не добавить: в typelib fontconfig нет `FcConfigAppFontAddFile`. Там остаётся копирование в `~/.local/share/fonts/modernclock/` и просьба перелогиниться. Сейчас оно сделано **синхронным** `Gio.File.copy`, и это кандидат на находку Shexli EGO-X-004, требующую асинхронный ввод-вывод ([пример EGO-X-004](https://github.com/rloutrel/gnome-extension-nvme-monitor/pull/38)). Для окна настроек есть отдельный путь: собственная `PangoCairo.FontMap.new()` с добавленными файлами, затем `window.set_font_map()` и `Gtk.FontDialog({font_map})` ([FontDialog:font-map](https://docs.gtk.org/gtk4/property.FontDialog.font-map.html)). Так не задеваются другие расширения в общем процессе приложения «Расширения». Ни одного расширения на EGO, которое уже использует `add_font_file`, найти не удалось, так что мы будем первыми.

## Поломки API 47–51, devkit и новые правила EGO

**Поломки API (подтверждено, gjs.guide).** `Clutter.Color` удалён в **47**, а не в 50, как ошибочно сказано в CLAUDE.md ([gjs.guide 47](https://gjs.guide/extensions/upgrading/gnome-shell-47.html)). St-свойство `vertical` устарело в 48 ([gjs.guide 48](https://gjs.guide/extensions/upgrading/gnome-shell-48.html)) и **удалено в 51**. В 51 также удалены `Clutter.get_default_backend()`, `Shell.GLSLEffect` и `pointerWatcher`, и `disable()` **не может быть async** ([gjs.guide 51](https://gjs.guide/extensions/upgrading/gnome-shell-51.html)). В 50 удалены X11, сигналы `restart` и `Meta.is_wayland_compositor()` ([gjs.guide 50](https://gjs.guide/extensions/upgrading/gnome-shell-50.html), [mutter NEWS](https://gitlab.gnome.org/GNOME/mutter/-/raw/main/NEWS)). Код уже ветвится между `set_orientation` (≥ 48) и `set_vertical` (< 48), а `disable()` синхронный. Изменений в `_backgroundGroup`, `monitors-changed`, `St.Label` и ellipsize не задокументировано. Это опирается на молчание гайдов, а не на явное утверждение.

**Тестирование на Wayland (подтверждено).** С GNOME 49 `--nested` больше нет. Вместо него `dbus-run-session gnome-shell --devkit --wayland`, которому нужен пакет `mutter-devkit` (Fedora) или, по непроверенным данным, `mutter-dev-bin` (Ubuntu 25.10+) ([gjs.guide Debugging](https://gjs.guide/extensions/development/debugging.html), [Fedora mutter-devkit](https://packages.fedoraproject.org/pkgs/mutter/mutter-devkit)). Наш `make test` вызывает `--devkit` без `--wayland`; это стоит выровнять по гайду. Заметки здесь расходятся. В mutter NEWS есть «Add multi monitor support to devkit» (!4828), эмуляция HiDPI (!4727) и создание мониторов devkit из командной строки (!4975, 51) ([mutter NEWS](https://gitlab.gnome.org/GNOME/mutter/-/raw/main/NEWS)), а GNOME 50 заявляет эмуляцию нескольких виртуальных дисплеев ([GNOME 50 developers](https://release.gnome.org/50/developers/)). При этом точного синтаксиса в первичной документации найти не удалось. Итог: мультимонитор в devkit **заявлен, но не проверен**. Горячей перезагрузки расширений на Wayland по-прежнему нет: цикл «правка → перезапуск devkit» занимает секунды.

**EGO и Shexli (подтверждено).** С 6 декабря 2025 отклоняются сабмиты с признаками AI-генерации: лишний код, «воображаемые» API, комментарии-промпты ([гайдлайны](https://gjs.guide/extensions/review-guidelines/review-guidelines.html), [блог Rahmatzadeh](https://blogs.gnome.org/jrahmatzadeh/2025/12/06/ai-and-gnome-shell-extensions/)). В июле 2026 появилась страница Best Practices. Она запрещает try/catch вокруг `destroy()`/`connect()`/`disconnect()`/`GLib.Source.remove()`, защитные `?.()` и `typeof === 'function'` для гарантированных API, а также запуск shell-команд ([Best Practices](https://gjs.guide/extensions/review-guidelines/best-practices.html)). Обратите внимание: feature-detect `typeof fm.add_font_file === 'function'` здесь оправдан, потому что API действительно зависит от версии Pango. Это нужно пояснить в заметках к ревью. Shexli (PyPI 0.2.1, `pip install shexli`) работает на страницах ревью EGO в статусе «experimental» ([PyPI](https://pypi.org/project/shexli/), [EGO review 71294](https://extensions.gnome.org/review/71294)). Его коды: EGO-P-006 (не включать `gschemas.compiled` для 45+), EGO-L-003/L-004 (сигналы и источники main loop снимать в `disable()`, даже если колбэк вернул `SOURCE_REMOVE`). Для CI есть `3v1n0/shexli-ci` с baseline-файлом и inline-подавлением ([shexli-ci](https://github.com/3v1n0/shexli-ci)). Обязательно ли проходить Shexli для загрузки, **не подтверждено**: первичные источники называют его рекомендательным. Текущее состояние проекта уже соответствует нескольким пунктам: в `src/schemas/` только XML, в `metadata.json` нет `version`, есть `settings-schema`, есть `make shexli`. CLAUDE.md всё это описывает устаревшим образом.

**Прочее в 50/51 (подтверждено).** Reduced Motion (50, в 51 распространён на анимации Shell) читается через `St.Settings.get().reducedMotion` (51). CSS-переменные `-st-accent-color`/`-st-accent-fg-color` доступны с 47 ([gjs.guide 47](https://gjs.guide/extensions/upgrading/gnome-shell-47.html)). Улучшено дробное масштабирование, 125%/150% ([GNOME 50](https://release.gnome.org/50/)). В 51 сглажено планирование кадров и исправлен blur на мониторах с невыровненными пикселями (!5115) ([GNOME 51](https://release.gnome.org/51/)). GJS перешёл на SpiderMonkey 140 (49+, есть `Temporal`), а `GLib.timeout_add_once()` появился с 50 ([GJS NEWS](https://gitlab.gnome.org/GNOME/gjs/-/raw/master/NEWS)). При поддержке 46+ полагаться на `Temporal` и `*_once` нельзя. `GnomeDesktop.WallClock` остаётся правильным источником тиков: его использует и верхняя панель Shell ([dateMenu.js](https://gitlab.gnome.org/GNOME/gnome-shell/-/raw/main/js/ui/dateMenu.js)). Работает ли `-st-accent-color` внутри inline `set_style()`, **не подтверждено**.

## Заключение

Сместилось понимание того, где на самом деле наши проблемы. Обходной путь со вторым монитором держался на диагнозе, который не подтверждается исходниками Clutter. Решение убрать его оказалось правильным по логике, но не проверенным на практике: это главный риск релиза 51. Проблема шрифтов, наоборот, выглядела нерешаемой, а на большинстве актуальных дистрибутивов (Ubuntu 25.04+, Fedora на GNOME 48+) теперь решается одним вызовом без записи на диск и без перелогина. Нужно только обращаться к нужной font map и не вызывать `config_changed()`. Нижняя граница поддержки (GNOME 46) — основной источник сложности: она мешает `add_font_file`, `Temporal`, `*_once`, async-prefs. Если со временем поднять минимум до 48, код заметно упростится и станет ближе к ожиданиям ревьюеров EGO.
